# Автоматизация первичной инициализации Bare-Metal серверов через Cloud-Init

Данный демонстрационный проект создан для отработки практических навыков автоматизации ранней настройки операционной системы (Bootstrap) применительно к выделенным серверам (Bare-Metal). 

Основной инструмент реализации — **Cloud-Init (user-data)**, который позволяет полностью исключить ручную конфигурацию системы сразу после ее установки.

### 🎯 Задачи конфигурационного скрипта:

1. **Разметка дискового пространства через LVM согласно стандартам индустрии:**
   Система инициализирует виртуальный диск и нарезает изолированные логические тома (Logical Volumes) для предотвращения переполнения корневого раздела (`/`), изоляции временных файлов (`/tmp`) и пользовательских данных (`/home`). 
   *Структура разметки основана на лучших практиках Enterprise-систем (по аналогии с шаблоном vg00-root, vg00-home, vg00-boot, vg00-tmp).*

2. **Обеспечение безопасного беспарольного доступа:**
   Создается первый непривилегированный пользователь с правами sudo. В целях безопасности аутентификация по паролям полностью отключается — доступ возможен только по строго заданным **SSH-ключам**. Нахождение открытых паролей в файле user-data недопустимо.

3. **Фиксация сетевого периметра (Брандмауэр):**
   На финальном этапе развертывания включается встроенный фаервол (ufw), который блокирует весь входящий трафик, кроме порта 22 (SSH). Это подготавливает изолированную систему к дальнейшему этапу конфигурации с помощью **Ansible**.

---

### ⚠️ ВАЖНОЕ ПРИМЕЧАНИЕ: Отказ от шифрования LUKS в демо-окружении

По стандартам индустрии при настройке реальных Bare-Metal серверов в "боевых" условиях поверх физических дисков в обязательном порядке разворачивается схема **LVM поверх LUKS** для обеспечения защиты данных в покое (Data-at-Rest Encryption). 

Однако в рамках данного демонстрационного проекта (разворачиваемого в облачной инфраструктуре Oracle Cloud) было решено отказаться от **LUKS** по следующим причинам:

* **Проблема удаленной загрузки (Headless boot):** Инициализация LUKS на этапе ранней загрузки требует интеграции с enterprise-системами управления ключами (KMS, Clevis/Tang) или ручного ввода passphrase через Serial Console, что ломает концепцию сквозной автоматизации (Unattended Installation).
* **Специфика виртуализации:** В облачных средах шифрование дисков безопаснее и эффективнее делегировать на уровень самого гипервизора (например, Oracle Block Volume Encryption), не нагружая процессор виртуальной машины гостевым шифрованием.
